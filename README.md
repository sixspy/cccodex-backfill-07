# cc-backfill-lab

CC_Codex 二期（26.11）**数据工程**产品线：**回灌补数台**（Falcon ASGI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**回灌窗口 → 按日切片计划 → 重放落库 → 覆盖对账**

与现有线正交（不是契约换版、水印、清单、留存、采集/ETL/同步/解析/编排/摄取）。
不碰外仓常见指纹（Feed 归并 / CDC 游标 / 质检签发 / Slicegate 类仓名）。

## 领域

- **所属领域**：数据工程
- **子方向**：数仓与数据湖（历史回灌 / 补数闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、Falcon ASGI、Uvicorn、SQLite |
| 前端 | 原生 JS SPA（全中文），靛青底 + 蜜橙强调；卡片墙，无侧栏/底栏 |

## 基线已通主链

1. 登记回灌窗口（目标表 / 起止日）
2. 生成按日切片计划
3. 单片重放落库
4. 计划覆盖对账

## 暂停 / 续灌（本期）

暂停后立刻续灌，续跑位点必须指向新片：偏移号、暂停策略卡片、续跑详情、回灌目录四处同看。

**位点落库只走路线 A：旁路位点账册。**
每次位点提交在 `BEGIN IMMEDIATE` 单写锁里先把现行偏移原子记进
`backfill_checkpoints`，再判定提交是否有效；无效位点写一条 `拒签` 流水后拒掉，
已成功片一行不动，旧位点在账册里仍可复核、但不能再当新位点灌。
路线 B（把半截重写行整笔回滚再挂新偏移）**未选**，两条不并挂。

| 表面 | 看什么 |
|------|--------|
| 位点列表 | 有效/拒签流水、提交偏移、现行偏移、原因码 |
| 续跑详情 | 现行偏移号、下一位点版本、下一片 |
| 暂停策略卡片 | 落库路线、现行偏移号、策略三条 |
| 回灌目录 | 每片状态与「下一片」高亮 |

拒签原因码：`STALE_CHECKPOINT` / `VERSION_AHEAD` / `SKIP_GAP` / `OVERWRITE_LOADED` /
`MISMATCH_PROGRESS` / `LOCK_BUSY` / `WINDOW_PAUSED` / `WINDOW_DONE`。
两名值班并发提交由写锁 + 每版本唯一有效位点索引兜底，至多一条有效。

预留切口（未做）：整窗失败闭 vs 单片独立事务、与在线灌数互斥、重叠窗拒入。
